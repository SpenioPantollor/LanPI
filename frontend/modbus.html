Unit ID Scan

        

          Probes a range of unit IDs with an FC3 request -- useful
          behind a Modbus TCP-to-RTU gateway serving several devices.
          A Modbus exception still counts as "responding": it proves a
          device is there, even if it rejected this specific probe.
          Sequential, one probe at a time -- not a burst.

Register Range Scan

        

          Finds which addresses are readable with no register map to
          go on -- probes whole blocks at once, only narrowing down
          (bisecting) where a block fails, so it doesn't cost one
          request per register. Capped at 10000 addresses per scan.

Live Register Polling

        

          Repeatedly reads one register (or block) on an interval,
          tracking response-time and success/timeout/exception
          statistics -- helps spot an unstable or overloaded device
          that a single read wouldn't reveal.

Passive Modbus TCP Traffic

        

          Observed from the shared background capture (TCP/502), not a
          separate listener -- shows every client/server relationship
          seen since start or last Reset. Limitation:
          this inspects individual captured packets without TCP stream
          reassembly, so a request/response split across TCP segments
          won't be counted, and "Missing" is a best-effort signal (a
          response this capture simply missed looks the same as one
          that was never sent) -- treat it as a hint to investigate
          further, not proof.
